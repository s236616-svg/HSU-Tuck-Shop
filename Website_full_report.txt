HSU TUCK SHOP
COMPLETE UI/UX, FUNCTIONAL LOGIC, DEMO DATA, AND PRODUCTION LIMITATIONS REPORT

Document purpose
================
This document is the single consolidated report for the current HSU Tuck Shop
prototype. It combines:

1. The UI/UX design details for every page.
2. The current interaction and application logic.
3. The role-based Student, Staff, and Admin functions.
4. The local demo data and browser persistence model.
5. The original list of backend, infrastructure, and production work that is
   not implemented in this front-end prototype.

The document describes the application as it exists now. It does not claim
that simulated functions are connected to real university or payment systems.


1. PROJECT OVERVIEW
===================

Project name
------------
HSU Tuck Shop

Project type
------------
A bilingual, responsive React + Vite front-end prototype for a university tuck
shop. It demonstrates online browsing, ordering, pickup, rewards, staff order
fulfilment, and administration.

Primary audiences
-----------------
- Students purchasing snacks, drinks, stationery, ice cream, and HSU merch.
- Staff preparing and handing over orders.
- Administrators managing inventory, pickup slots, users, and reports.

Current technology
------------------
- React 19 for interface components and local state.
- Vite for development and production builds.
- TypeScript for data types and component contracts.
- Tailwind CSS v4 is available through the Vite plugin.
- Most custom visual styling is implemented in src/index.css.
- Browser localStorage provides demo persistence.
- No backend, database, real payment gateway, or real email service is
  connected.

Current product catalogue
-------------------------
- 56 tuck-shop products imported from the supplied product table.
- 15 HSU merchandise products.
- 71 products in the combined inventory.
- Product names are available in English and Traditional Chinese.
- Product categories are snacks, drinks, stationery, ice cream, and HSU merch.
- Product images are stored locally under src/assets/products and
  src/assets/merch.

3. DESIGN SYSTEM AND VISUAL LANGUAGE
====================================

Brand direction
---------------
- Friendly campus convenience-store identity.
- Deep green is the primary brand colour.
- Milky green and warm neutral surfaces support the main brand colour.
- Gold is used for highlights, stamps, rewards, and important accents.
- Red is used for destructive actions, cancellation, and favourite hearts.
- Rounded cards and controls create a friendly, approachable tone.
- The custom panda mascot gives the prototype a recognizable campus character.

Typography
----------
- Inter is used for general interface copy.
- Nunito is used for strong display headings and friendly brand emphasis.
- Noto Sans TC is used for Traditional Chinese content.
- Headings use bold weights and compact spacing.
- Supporting labels use smaller sizes, muted colours, and uppercase or
  letter-spaced treatments where appropriate.

Layout
------
- Desktop content is centered inside a maximum-width content container.
- Major pages use cards, grids, tables, banners, and clear page introductions.
- The desktop header remains the primary global navigation.
- Mobile uses a fixed five-item bottom navigation.
- Staff and admin tables can scroll horizontally on smaller screens.
- Product grids reduce their column count at tablet and mobile breakpoints.
- Checkout changes from a split content/summary layout to a single-column
  mobile layout.

Themes
------
- Light theme.
- Dark theme.
- System theme, which follows the operating-system preference.
- Theme choice persists in localStorage.
- Login pages use a special green-to-light or green-to-black gradient.
- The Home page keeps its own solid milky-green visual treatment.

Language
--------
- English.
- Traditional Chinese.
- Language choice persists in localStorage.
- Product names show a primary language and a secondary translated name.
- Most controls, status labels, validation messages, and page headings are
  translated through src/i18n.ts.

Interaction feedback
--------------------
- Selected tabs, chips, payments, and pickup slots receive visible active
  states.
- Hover states and small card movement reinforce clickability.
- Buttons use primary, secondary, gold, text-link, and danger treatments.
- Toast messages communicate actions such as collection, restocking, and demo
  order reset.
- Empty states use the panda mascot and a clear next action.
- Loading states use a compact spinner.
- Form errors appear beside the relevant input or in an error banner.

Iconography and imagery
-----------------------
- Interface icons use a consistent outline SVG style.
- Password fields use open-eye and closed-eye icons.
- The panda mascot has full, head/mark, line-art, and shop variants.
- Earned TS Stamps use borderless panda-head artwork.
- Product images are local assets rather than remote runtime dependencies.

5.1 LOGIN PAGE (/login)
-----------------------
Purpose:
- Authenticate a demo user and establish a local session.

UI/UX:
- Unified green gradient across the visual and form areas.
- HSU Tuck Shop branding and panda artwork.
- Email and password fields.
- Password visibility toggle with open/closed eye icon.
- Remember-me option.
- Forgot-password link.
- Primary sign-in button.
- Simulated Google sign-in.
- Continue-as-guest option.
- Registration link.
- Demo credential hint.

Logic:
- Reads users from hsu-users in localStorage.

- Guest continuation is a prototype interaction, not a secure guest account.

5.11 CHECKOUT OVERLAY
---------------------
Purpose:
- Demonstrate a three-step pickup and payment workflow.

Step 1: Pickup
- Shows the selected pickup location.
- Displays all configured pickup slots.
- Full slots are visibly disabled and cannot be selected.
- Remaining spaces are calculated as capacity minus booked count.
- If every available slot is full, an explanatory message appears and Continue
  is disabled.
- The selected slot controls the location shown in checkout.

Step 2: Payment
- Provides seven selectable demo methods:
  HSU Wallet, Octopus, AlipayHK, WeChat Pay HK, PayMe, Visa/Mastercard, and
  Counter.
- Every method can be selected.
- Selected payment receives a clear visual state.
- HSU Wallet displays the HK$99,999 demo balance.
- Other methods are marked simulated.
- No external application or payment provider is launched.

Step 3: Review
- Shows pickup date/time.
- Shows pickup location.
- Shows the selected payment method.
- Includes a terms confirmation checkbox.
- Place Order opens the success screen.

Additional logic:
- Cancel simulated payment opens a confirmation overlay.
- Completing checkout clears the cart and shows Success.
- It does not create a new durable order record in the order list.
- It does not charge any payment provider.

6. SHARED COMPONENT AND FUNCTION REFERENCE
==========================================

src/App.tsx
-----------

pageFromPath(path)
- Removes the query string.
- Finds the matching Page value from pagePaths.
- Falls back to Home.

Icon({name, size})
- Renders reusable outline SVG paths from the local icon map.

ThemeControl({theme, setTheme, t})
- Renders Light, Dark, and System segmented buttons.
- Defined as a reusable control; compact header settings use select elements.

LanguageControl({lang, setLang, t})
- Renders English and Traditional Chinese segmented buttons.

Header(...)
- Controls desktop navigation, notification dropdown, cart badge, account
  button, account drawer, role navigation, and role switching.
- Uses a ref plus a document pointer listener to close notifications on outside
  click.

MerchNotice({t})
- Renders the merchandise purchasing notice.

PurchaseInfo({t, catalog})
- Renders location, office hours, payment, enquiry, and bag information.
- Uses different copy for catalogue and product-detail contexts.

isMerch(product)
- Treats IDs of 100 or higher as HSU merchandise.

productName(product, lang)
- Returns English or Chinese as the primary product name.

ProductCard(...)
- Renders one product.
- Handles favourite persistence, details opening, and adding to cart.

Home(...)
- Renders hero, categories, featured products, drop, and TS Stamp promotion.
- Passes selected category into Shop navigation.

Shop(...)
- Maintains selected category and query.
- Filters active products and renders catalogue/merch information.

Empty({t})
- Shared panda-based no-results state.

ProductDetail(...)
- Maintains option choice, quantity, and favourite state.
- Displays different detail controls for tuck-shop and merchandise products.

Cart(...)
- Resolves cart IDs against shared inventory.
- Calculates line totals and full order total.

Checkout(...)
- Maintains step, selected slot, selected payment, and cancellation state.
- Prevents continuation when no pickup slot is available.

Success(...)
- Renders simulated confirmation, QR, fallback code, and pickup details.

PickupQrGraphic()
- Reusable decorative pickup QR SVG.

Orders(...)
- Filters orders by tab.
- Handles cancellation, buy again, and pickup QR display.
- Persists order changes.

Login(...)
- Legacy simple login component retained in App.tsx.
- The active route uses AuthScreen from SuitePages.tsx instead.

Switch(...)
- Generic local toggle.
- Optionally persists a Boolean and toggles an HTML class.

Account(...)
- Handles profile editing, image upload, wallet demo credit, password change,
  session list, role switching, and local account deletion.

Dashboard(...)
- Uses one component for Staff and Admin variants.
- Staff variant handles order stages and pickup verification.
- Admin variant handles KPI display and low-stock restocking.
- resetOrders restores initialOrders.

BottomNav(...)
- Renders responsive mobile navigation and cart badge.

App()
- Main state owner and page compositor.
- Initializes demo seed and current user.
- Owns language, theme, session, role view, orders, slots, notifications,

7. APPLICATION STATE AND LOGIC MODEL
====================================

Shared React state
------------------
- page: current route/page.
- lang: en or zh.
- theme: light, dark, or system.
- user: active DemoUser.
- loggedIn: based on hsu-session.
- view: student, staff, or admin.
- orders: current demo orders.
- slots: pickup-slot records.
- notifications: notification records.
- inventory: combined products with editable stock/price/image/active state.
- shopCategory: category selected before opening Shop.
- cart: product ID -> quantity.
- selected: product shown in Product Detail.
- checkout: whether checkout overlay is open.
- success: whether success overlay is open.

Browser persistence keys
------------------------
hsu-demo
- Indicates initial seed has run.

hsu-users
- Demo user records, passwords, roles, profile data, and avatar data URL.

hsu-session
- Current local user ID.

hsu-auth
- Local logged-in demonstration flag.

hsu-view
- Selected Student/Staff/Admin view.

hsu-lang
- en or zh.

hsu-theme
- light, dark, or system.

hsu-orders
- Order records and stage transitions.

hsu-slots
- Pickup times, location, booked count, and capacity.

hsu-notifications
- Notification content and read state.

hsu-inventory
- Saved inventory price, stock, image, enabled state, additions, and deletions.

hsu-favs
- Favourite product IDs.

Additional switch keys
- Some settings switches use their own local keys.

Persistence behavior
--------------------
- Data persists only in the same browser storage.
- It is not shared between devices, browsers, or users.
- Clearing browser storage resets local data.
- Uploaded images can consume localStorage capacity because they are data URLs.
- localStorage is not secure and must not hold production passwords or tokens.

12. RECOMMENDED PRODUCTION LOGIC
================================

Authentication
--------------
1. Browser submits credentials over HTTPS.
2. Server validates input and compares a password hash.
3. Server returns a secure HTTP-only session cookie.
4. Server checks role authorization on every protected request.

Checkout
--------
1. Server recalculates all prices from database records.
2. Server verifies product availability.
3. Server reserves stock and slot capacity in a transaction.
4. Server creates a pending order.
5. Payment provider confirms payment through a signed callback/webhook.
6. Server marks the order paid and sends confirmation.

Pickup
------
1. Server issues a signed, expiring pickup token.
2. Staff scanner validates the token server-side.
3. Server checks order status and prevents replay.
4. Collection and inventory events are written atomically to an audit log.

Stock management
----------------
1. Admin changes are validated server-side.
2. Product and stock updates are stored in a database.
3. Image uploads use validated object storage.
4. Every edit creates an audit event.

Loyalty
-------
1. Eligible paid/collected order value is accumulated server-side.
2. One stamp is awarded per HK$25 cumulative eligible spending.
3. Redemption occurs in a transaction and cannot be duplicated.

14. FINAL REPORT SUMMARY
========================

The HSU Tuck Shop prototype demonstrates a complete multi-role campus retail
experience in one responsive bilingual interface. It includes product
discovery, favourites, cart, pickup-slot selection, simulated payment, order
tracking, TS Stamp rewards, staff fulfilment, inventory editing, slot
management, user roles, analytics, developer examples, and audit presentation.

The prototype is effective for UI/UX evaluation and a college project
demonstration because state changes are interactive and many values persist in
the same browser. However, localStorage and React state are not replacements
for authentication, authorization, databases, transactions, payment services,
email delivery, or secure APIs. Production deployment requires the backend,
security, infrastructure, and operational work listed above.
